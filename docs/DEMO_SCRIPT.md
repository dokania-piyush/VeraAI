# Show behavior, not a feature list

This is a suggested demonstration outline, not a claim that a video was recorded.

Start with the premise: “This bot can explain why it chose a message, and it remembers what it promised.” Open the studio's price case. Show the current merchant price and the competitor's separate price. Evaluate, change the merchant price, and evaluate again. Point to the source paths rather than claiming a model has verified the real world.

Next, run the local HTTP demo. It pushes a higher-version price update between the invitation and “yes.” Show the actual returned draft, including that it has not been published. Explain how binding the pending offer by ID prevents a reordered offer list from switching the proposal.

Then show the service-quality case: review mentions lead to a useful delivery-status reply rather than an invalid weekday discount. Show the customer reminder and revoke consent; the preview abstains. Finish with the real STOP flow from the transcript, where a new trigger is suppressed by separate recipient state.

Close with one honest boundary: “The source code and behavior checks run. This is not proof of merchant engagement or a private-judge score. The next validation is copy quality on unfamiliar cases and the final hosted endpoint.”

Before presenting, replace metadata, inspect the source, and explain the tradeoffs in your own words. Do not conceal AI assistance or use someone else's identity.
